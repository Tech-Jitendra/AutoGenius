# AutoGenius — Database Design (PostgreSQL)

Naming: `snake_case` tables/columns. Primary keys are UUIDs. Timestamps are `timestamptz`.
Migrations are managed with the API's migration tooling (introduced with the Auth task).

## Entity Relationship Summary

```
users 1─∞ vehicles 1─∞ vehicle_service_records
              1─∞ maintenance_items
              1─∞ expenses
users 1─∞ ai_conversations 1─∞ ai_messages
users 1─∞ quotations 1─∞ quotation_items
```

### refresh_tokens

Refresh credentials are stored only as SHA-256 hashes of the presented token;
the plaintext token exists only on the client. Rotation marks the old row
revoked and points it at its replacement; presenting a revoked hash revokes
every session of that user (reuse detection).

| Column          | Type          | Notes                    |
| --------------- | ------------- | ------------------------ |
| id              | uuid PK       |                          |
| user_id         | uuid FK→users | CASCADE on delete; INDEX |
| token_hash      | varchar(64)   | sha256 hex; UNIQUE       |
| expires_at      | timestamptz   |                          |
| revoked_at      | timestamptz   | nullable                 |
| replaced_by_id  | uuid          | nullable; rotation chain |
| created_at      | timestamptz   |                          |

UNIQUE INDEX: `(token_hash)`. INDEX: `(user_id)`.

### vehicles

Every read and write is scoped by `user_id` as well as the vehicle id, so a foreign
vehicle is indistinguishable from a missing one. The application takes a `FOR UPDATE`
lock on the owner's `users` row for the whole transaction, which makes "the first
vehicle is the default" and "promote this vehicle" deterministic; the partial unique
index below is the backstop if that ever breaks.

| Column              | Type         | Notes                          |
| ------------------- | ------------ | ------------------------------ |
| id                  | uuid PK      | generated by the API           |
| user_id             | uuid FK→users| NOT NULL; INDEX; CASCADE on delete |
| make                | varchar(50)  | NOT NULL                       |
| model               | varchar(50)  | NOT NULL                       |
| variant             | varchar(50)  | nullable                       |
| registration_number | varchar(20)  | nullable; stored normalised to upper case |
| manufacturing_year  | int          | NOT NULL; CHECK 1900…2100      |
| fuel_type           | varchar(20)  | NOT NULL; CHECK PETROL/DIESEL/CNG/HYBRID/ELECTRIC |
| transmission        | varchar(20)  | NOT NULL; CHECK MANUAL/AUTOMATIC/AMT/CVT |
| purchase_date       | date         | nullable; date-only so no timezone shift |
| current_odometer    | integer      | nullable; CHECK 0…2000000      |
| is_default          | boolean      | NOT NULL DEFAULT false         |
| created_at          | timestamptz  |                                |
| updated_at          | timestamptz  |                                |

INDEX: `(user_id)`, `(user_id, created_at DESC)`.
UNIQUE INDEX: `(user_id) WHERE is_default` — at most one default per user.
UNIQUE INDEX: `(user_id, regexp_replace(upper(registration_number), '[^A-Z0-9]', '', 'g'))
WHERE registration_number IS NOT NULL` — plates are unique per owner, compared on a
canonical key that ignores case and separators (`MH 12 AB 1234` and `mh-12-ab-1234` are
one plate), while the row keeps the readable stored value. Vehicles without a plate never
collide.

`fuel_type` and `transmission` are `varchar` + CHECK rather than PostgreSQL enum types so
that adding a value is a data change, not a `TYPE` migration.
